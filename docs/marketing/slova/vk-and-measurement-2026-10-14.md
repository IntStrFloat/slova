## Наблюдаемая воронка

| Этап | Определение / источник | Текущий разрыв и альтернативы |
|---|---|---|
| Показ → клик | CTR=clicks/shows; VK, полный день и неизменная версия объявления | Низкий CTR может отражать placement/частоту/состав аудитории, а не только изображение |
| Клик → установка VK | Install result по правилам VK; CPI=расход VK/results | Отношение установок к кликам не универсальная конверсия карточки: возможны другие окна/типы атрибуции и прямые установки |
| Карточка → установка | Собственные просмотры/установки RuStore, если доступны в консоли | Не подменять просмотры карточки всеми VK-кликами |
| Установка → first_open | Уникальные SDK identities с metadata установки и первым запуском | Провал может быть совместимостью, отменой установки, повтором, временем или трекером |
| first_open → первая победа | Уникальные пользователи с `first_level_completed`, завершение L1 | L1 включает обучение, потому не главная метрика самостоятельной ценности |
| Самостоятельная победа | `independent_level_completed` на L2–L5 без помощи, не более1 на пользователя | Главная ранняя активация. Нужны точное окно24ч после реальной установки и подтверждённый install source |
| L5 / открытка | `fifth_level_completed`; отдельно проверка факта получения открытки, если событие доступно | Не выводить получение открытки только из клика по рекламе путешествий |
| D1/D7 игра | Уникальный новый пользователь с реальным игровым действием в календарный Dn МСК / все подходящие новые пользователи зрелой когорты | Бонус, доставка напоминания или один app-open не считаются игровой активностью |
| Доход | Когортный накопленный рекламный + подтверждённый платёжный доход, одна валюта и окно | Календарный доход старых игроков не LTV закупленных. Не считать UI-подписку выручкой |

Идентификаторы пользователей — только в защищённой исходной выгрузке; отчёт хранит агрегаты. Не угадывать рекламный источник из `game_session_start.source=direct`.

Дедупликация: SDK identity + event_id; новая установка отдельно от обновления/повтора; завершение — по игроку и puzzle key. Для Dn исключить незрелые дни, QA и известные тестовые устройства. Отдельно показывать `unknown_source`, пропуски install metadata и долю событий без нужной версии. Проверять объединение по идентичности, а не складывать unique users разных событий.

`Activation24h = unique independent winners within24h / eligible new installs with full24h`. `CPA_active = соответствующий расход / такие игроки`. `D7_play = игровые возвраты в день7 / новые игроки с полностью наблюдаемым днём7`. ## EXP-01 — сообщение и качество привлечённого игрока

- **Статус:** draft protocol, не запущенный новый эксперимент. Вход: CR-01/02/03 и SEG/MSG из стратегии, EVD-05/07/08/10. Вопрос: какая подача приводит к самостоятельной победе и возвращению, а не только дешёвой установке?
- **Условия старта:** закрыты P0; новая версия каждого объявления допущена и доставляется; известны версия игры, окно атрибуции и остаток бюджета. Если AppMetrica недоступна, текущая доставка остаётся наблюдением установок; новые транши на сравнение качества не открываются.
- **Дизайн:** сначала читать существующую группу, фиксируя дату и версию каждой подачи. Общий старт сравнения всех трёх — не раньше15.10 и после фактического начала доставки. Рекламу, карточку и onboarding одновременно не менять. Внутри существующей алгоритмической доставки сравнение наблюдательное; оно не доказывает причинный эффект текста.
- **Окно:** 7полных сопоставимых дней; предварительная проверка технического пути каждый рабочий день. Затем дождаться D7 последних установок и ещё48ч на возможное доначисление. При изменении версии открывается новая когорта; период до изменения сохраняется.
- **Ограничение:** до6000 ₽ внутри общей строки VK15000 ₽, суммарно не более500 ₽/день. Остаток учитывает уже идущую доставку. Лимит, время и объём не требуется обязательно исчерпать.
- **Минимум для содержательного отчёта:** целевой ориентир100 связанных установок на сравниваемую подачу и30 активаций; это рабочая минимальная база, не расчёт статистической мощности. При недоборе к окончанию окна/лимита результат `inconclusive`, не автоматическое продление или повышение ставки.
- **Основная метрика:** CPA_active24h. Ограничители: доля самостоятельных побед, D1/D7_play, ошибка установки/первого запуска. CTR/CPI — диагностические. Для долей указывать числитель/знаменатель и интервалы неопределённости; для расходов — период и версию.
- **Решение:** низший CPA_active при сопоставимой доставке и без обнаруженного ухудшения качества — кандидат на повтор, не победитель. При неопределённости сохранить обе подачи. Если выборка мала, не объявлять отсутствие вреда доказанным. Следующий транш до6000 ₽ — повтор на новой недельной когорте, внутри того же месячного лимита.
- **Остановка:** дефект установки/учёта, неподтверждённое обещание, модерация или исчерпанный лимит → остановить новый тест до исправления. Изменение живой кампании выполняется как отдельная конкретная операция с чтением результата, в этом аудите не выполнено.

Существующие автоматические правила замен хранятся в EVD-08: для нуля64 ₽ +48ч ожидания; для сравнений CPI дополнительные условия, полные дни и повторные подтверждения. Это уже отдельный процесс, не новый эксперимент. Перед EXP-01 согласовать один владеющий процесс на кампанию: если автоматизация заменяет креатив, записать вмешательство, закрыть прежнее окно и не приписывать весь период одной версии. Автоматизацию здесь не меняли и новую не создавали.

Недодоставка проверяется в порядке: доступ/статусы → moderation → совместимость/placements → аудитория/исключения → ставки/аукцион → баланс/расписание. Лишь после исключения технических причин можно проверять ставку как отдельный фактор. Не повышать дневной лимит, когда он и так не выбирается.

## EXP-02 — понятность первого скриншота

- **Статус:** draft. Вход: наблюдения5новых пользователей, текущая карточка, реальный L1, MSG-01. Гипотеза: крупное игровое поле с ясным действием лучше объясняет механику.
- **Вариант A:** текущий первый скриншот. **Вариант B:** реальный экран с читаемыми буквами и короткой подписью о соединении букв. Не рисовать несуществующие интерфейсы, денежные призы или обещание отсутствия рекламы.
- **Сначала:** показать оба варианта по отдельности в переменном порядке; попросить объяснить действие и ожидаемый результат. Повторяющееся непонимание — причина доработки, а не основание закупать больше трафика.
- **Затем:** проверить доступность A/B в RuStore и достаточность просмотров; при доступности50/50, один меняемый элемент, стабильная версия/источники, 14полных дней, окончательные результаты после пересчёта платформы. Часть прямых установок может обходить карточку — учесть её отдельно.
- **Метрика:** установки/просмотры соответствующего варианта по определениям RuStore. Связанный gameplay — только если назначение варианта доступно в данных; не выдумывать такую связку. При недоборе — `inconclusive`, а не последовательное до/после под видом A/B.
- **Ресурс:** материалы из строки3000 ₽, трафик из существующей VK-строки; дополнительного бюджета не добавлять. Этот тест не запускается параллельно с изменением креативов EXP-01, если их влияние невозможно разделить.

Поддержка тестов описаний/скриншотов/видео подтверждена [справкой RuStore](https://www.rustore.ru/help/developers/advertising-and-promotion/a-b-experiments). Конкретная доступность и допуски аккаунта остаются pending.
