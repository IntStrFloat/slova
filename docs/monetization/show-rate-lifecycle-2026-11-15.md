# Проверка и исправление жизненного цикла рекламы

Дата: 15 ноября 2026. Область: Android, Yandex Mobile Ads RN 8.5.0, Expo 56.

## План до изменения кода

1. Зафиксировать поведение: исходные 25 наборов монетизации / 421 тест проходят. Добавить регрессии до исправлений для загрузки без допустимого размещения, скрытого баннера, потери callbacks и устаревших событий.
2. Убрать безусловную предзагрузку interstitial при запуске и после закрытия. Подготавливать один объект рядом с допустимой игровой паузой, используя действующую политику частоты. Не запрашивать рекламу без рекламы / в первой защищённой сессии. Сохранять ещё пригодный объект при временном уходе с экрана, не отменять load с незавершённым Promise.
3. Баннер запрашивать только на активном видимом экране. Не вводить собственный refresh; закрепить callbacks за своим запросом и освобождать native view корректно.
4. Исправить Android interstitial dispatch, освобождение объектов и безопасное восстановление fullscreen при пропавшем terminal callback. Старое событие не освобождает новую операцию. Сохранять earned-подтверждения и восстановление rewarded.
5. Не добавлять новые аналитические события, зависимости или рекламные форматы. Существующие события оставлять вне критического пути. Проверить дубли запросов и callbacks.
6. Проверить регрессии, lint, TypeScript, существующий static analysis и Android-сборку. Runtime-проверку выполнять только на временном принадлежащем этой сессии устройстве, с обязательным удалением после тестов.

## Критерии приёмки

- Один loader и не больше одного load в полёте / готового объекта на формат.
- Нет interstitial-запросов без допустимого игрового размещения и для removeAds.
- Временный отказ в показе не потребляет готовый объект.
- Ошибка / закрытие / поздний дубль не блокируют последующие показы и не снимают чужую блокировку.
- Таймаут возвращает управление игре, но не разрешает второй fullscreen поверх подтверждённого активного native-показа.
- Нет баннерных запросов от скрытого route; обычный render не перезагружает баннер.
- Награда выдаётся по earned-событию и сохраняется идемпотентно; закрытие не выдаёт награду.

## Ограничение вывода

77,97% — совокупный Show Rate из скриншота за незаконченный день, без разбивки по форматам и версиям. Найденные дефекты не доказывают причинность всех 22,03% непоказанных подборов. После выпуска сравнивать законченные дни по форматам, показам и доходу на игрока; повышение одного отношения сокращением полезных загрузок не является самостоятельным успехом.

## Реализовано

- `frequency.ts`, `remote-config/consumption.ts`, `game.tsx`, `useAdGameplayClock.ts`: одна межстраничная реклама подготавливается не раньше чем за одно возможное завершение кампании либо за 30 секунд видимого игрового времени до допуска. Это обратимый запас на загрузку, не новая частота показов. Используется текущая remote-конфигурация без регистрации аналитической экспозиции при подготовке. Первая сессия, обучение, daily, защищённые переходы и removeAds отсекаются. Фактический показ по-прежнему проходит исходную политику; ошибки подготовки не задерживают переход.
- `yandexAds.native.ts`: запуск приложения больше не означает interstitial-запрос; после потребления нет безусловной заготовки на полный cooldown. Готовый объект сохраняется при временном скрытии, запрещены дубли load, removeAds освобождает неиспользуемый объект, включая поздний результат загрузки. Для interstitial добавлены watchdog и подтверждение реального native-владения; старые callbacks не снимают чужой lease. Дублирующий обработчик ошибки показа объединён.
- `AdBanner.native.tsx`: запросы только от foreground/focused route без занятого fullscreen lease, отмена устаревшего расчёта размера, собственная неизменная идентичность каждого native view и защита от поздних callbacks. Обычные renders не пересоздают запрос. Собственного refresh нет. Проверка на устройстве показала, что AppState сам по себе не предотвращает обновление баннера за AdActivity: в первом QA-прогоне были обновления примерно раз в минуту во время видимого interstitial. Поэтому баннер снимается на время shared fullscreen; SDK 8.5 не предоставляет отдельного pause/resume.
- `patches/yandex-mobile-ads+8.5.0.patch`: interstitial show проверяет текущую resumed/focused Activity, завершает dispatch Promise, освобождает объекты при terminal failure. Dispose активного показа сохраняет необходимые callbacks; native lifecycle подтверждает отсутствие рекламы. Ошибка обновления баннера больше не теряет ссылку на native view. Все прежние девять файлов patch сохранены, rewarded-журнал не переписан.
- Одно готовое rewarded-объявление сохранено для мгновенного добровольного показа. Удаление этой предзагрузки ради роста отношения могло бы ухудшить доступность наград. Analytics hooks уже изолированы от критического пути и дедуплицированы; новые типы событий и зависимости не добавлялись.

## Дополнительное исправление по Android-наблюдению

Второй QA-прогон подтвердил, что одного React-unmount при fullscreen lease недостаточно: native auto-refresh продолжался примерно раз в минуту, пока Fabric/React host был paused. В Android `YandexBannerView` исходные `onHostPause`/`onHostResume` были пустыми. Добавлено синхронное освобождение SDK view на hostPause/detach, однократное восстановление только при attached/shown/resumed view с положительными размерами и отдельный listener каждого экземпляра. Поздний callback уничтоженного SDK view игнорируется по его идентичности.

SDK view сохраняет исходный themed Context. Для проверки lifecycle используется настоящий `ReactApplicationContext`: `ThemedReactContext` делегирует регистрацию listener, но не значение `lifecycleState`. Недокументированный inherited-метод управления refresh из обфусцированного superclass SDK не используется; выбран публичный `destroy()`.
