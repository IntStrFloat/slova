# Запрос отдельного API чеков НПД для оплат через ЮKassa

Проверено 5 октября 2026 года. Выбранная схема: самозанятый без ИП принимает оплату собственной Android-игры через ЮKassa; отдельный уполномоченный партнёр регистрирует чеки НПД и обеспечивает их доставку. Подписка стоит 99 ₽ каждые 30 дней с автопродлением. Ориентир для оценки стоимости — 13 платежей в месяц; это сценарий прогноза, а не фактическое число продаж.

**Подключение подходящего провайдера пока не подтверждено.** MonetaNPD имеет публичные методы регистрации и аннулирования чеков, но опубликованный порядок описывает подключение маркетплейса. Пригодность этого договора для одного физлица на НПД, работающего через внешнюю ЮKassa, и тариф нужно получить письменно. Реализация конкретного адаптера начинается после подтверждения этих условий и выдачи документированных тестовых реквизитов.

## Готовое письмо в MonetaNPD

Платежи и возвраты будут проходить через ЮKassa. Нужен отдельный официальный API для автоматической регистрации дохода и чеков НПД в «Моём налоге» по этим платежам.

В вашей документации нашёл `registerincome` и `cancelreceipt`. Прошу подтвердить условия именно для следующей схемы: один продавец — физлицо на НПД без ИП, покупатели — физлица, внешний эквайринг — ЮKassa, без проведения платежей и выплат через Монету.

4. **Дата расчёта и сумма.** Как указать исходную дату и время расчёта, часовой пояс и вид плательщика? ## Что пока не разрешает публичная документация MonetaNPD

Эти пункты являются пробелами в просмотренной документации, а не утверждением, что провайдер не поддерживает нужные функции.

| Операция | Подтверждено документацией | Что уточнить до реализации |
| --- | --- | --- |
| Подключение | Заявка от маркетплейса, `security_key` и `secret_key`, регистрация физлица и ЭСП | Договор для одного физлица НПД; внешние платежи ЮKassa; тариф и необходимость ЭСП |
| `POST /npdapi/registerincome` | `key`, `amount`, `desc`, `inn`, подпись `md5(amount + desc + inn + SecretKey)`; `sync`; в успешном результате `aisReceiptId` и `aisReceiptLink` | Внешний идемпотентный ID и поиск по нему; исходная дата расчёта; email покупателя и доставка |
| `POST /npdapi/registerofflineincome` | Сценарий на случай отсутствия результата из-за недоступности ФНС | Безопасный переход к нему после неопределённого ответа; отсутствие дублей; исходная дата. «Offline» здесь не означает доход вне Монеты |
| Уведомление о чеке | Описан результат с ID/ссылкой на чек | Подпись callback, повторы, конечные ошибки, API сверки |
| `POST /npdapi/cancelreceipt` | `key`, `inn`, `reason`, `receiptid`, `signature`; синхронный метод без callback; `checkIsDeleted` | Формула подписи; допустимые причины; сверка неопределённого результата и повтор; частичный возврат |
| `POST /npdapi/refund` | Возвращает деньги по операции Монеты; отмена чека вызывается отдельно | Для платежа ЮKassa этот денежный метод не используется; согласовать самостоятельное аннулирование чека |

Источники: [регистрация дохода](https://docs.payanyway.ru/marketplace/samozanyatye/scenarii-ispolzovaniya-npd-api/8.-registraciya-dokhoda-v-fns-i-8.-pechat-cheka), [режим при недоступности ФНС](https://docs.payanyway.ru/marketplace/samozanyatye/scenarii-ispolzovaniya-npd-api/6.-zapros-na-registraciya-dokhoda-samozanyatogo-offline-rezhim), [аннулирование чека](https://docs.payanyway.ru/marketplace/samozanyatye/zaprosy-dlya-raboty-s-fns/8.-zapros-na-stornirovanie-cheka), [денежный возврат](https://docs.payanyway.ru/marketplace/samozanyatye/zaprosy-dlya-raboty-s-fns/29.-vozvrat-po-operacii).

Публичная схема не определяет безопасный повтор создания после потери ответа до получения ID запроса. Подставлять собственный параметр идемпотентности или считать одинаковую подпись защитой от дублей нельзя. Требуется документированный контракт провайдера.

| Т-Банк | [API получения чеков](https://developer.tbank.ru/docs/api/self-employed-receipts) требует платёжный реестр и доступ Т-Бизнеса к самозанятым компании. Это не подтверждает личный API чеков по входящим платежам ЮKassa |
| Точка | [Документация расчётов](https://developers.tochka.com/docs/cyclops/terminologia) описывает номинальный счёт площадки и средства её клиентов. Возможность использовать отдельный НПД API одному продавцу без ИП не подтверждена. Сервис «Чеки» по 54-ФЗ не считать заменой чека НПД |
| Банк 131 | [Официальные методы](https://developer.131.ru/en/reference/methods) описывают выплаты с фискализацией `session/init/payout/fiscalization`. Самостоятельное подключение физлица НПД только для чеков по входящим платежам ЮKassa не подтверждено |

## Авторизация следующего шага и критерии готовности

Можно отдельно поручить отправить приведённый технический запрос на **marketplace@support.payanyway.ru** и, при необходимости, на **support@selfwork.ru**. Разрешение сохранить ЮKassa и найти провайдера само по себе не является поручением отправить сообщение. Сейчас документ — только черновик запроса.

После ответа потребуется выбрать предложенный тариф и оформить договор, пройти проверку продавца и лично выдать партнёру согласованные права в «Моём налоге». До получения цены и условий акцепт не подготовлен. API-ключи передаются безопасно и сохраняются на backend вне git; личный пароль ФНС не используется.

Для включения автоматических чеков нужны:

- Письменное подтверждение схемы «самозанятый без ИП + внешняя ЮKassa» и полный тариф.
- Документированный API, тестовый доступ и механизм исключения дублей после потерянного ответа.
- Подтверждённые дата расчёта, создание чека, доставка покупателю, полная отмена и частичный возврат.
- Проверенные действия при недоступности ФНС, отзыве прав и утрате статуса НПД.
- Боевые реквизиты и подтверждение полномочий партнёра; затем контролируемая проверка реальной регистрации/доставки чека по согласованному платежу.

Сам факт установки API-ключа или флага готовности не подтверждает выдачу чека. Общие условия запуска подписки описаны в [runbook ЮKassa](yookassa-subscription.md). Закрытие чеков НПД ЮKassa зафиксировано в [журнале API, запись 23 декабря 2025 года](https://yookassa.ru/developers/using-api/changelog).
