# Игровая область под адаптивным Sticky-баннером — 30.10.2026

## Анализ игровой вёрстки

- Баннер уже находится отдельным нижним элементом внутри `SafeAreaView`, вне прокрутки поля. Его реальная высота уменьшает flex-область игры; `onLayout` измеряет остаток. Повторно вычитать баннер из высоты игры не требуется.
- Поле и задачи прокручиваются, колесо букв остаётся фиксированным. Минимальный размер колеса и букв сохраняет удобство ввода. При очень короткой оставшейся области фиксированное колесо может занять всё место и выйти за границы игры.
- Собственная плашка «Реклама» в текущем игровом JSX отсутствует. Размер 56 dp относится к кнопкам подсказок и не является ограничением баннера.

## План реализации

1. Запустить существующие целевые тесты вёрстки и игрового экрана; добавить регрессию изменения высоты области и получить ожидаемый красный результат до исправления.
2. Сохранить текущий расчёт сетки и минимальные размеры букв. Добавить ограниченную прокрутку всей игровой области только когда для поля после колеса остаётся меньше 96 dp (примерно три минимальные строки).
3. Ограничить отрисовку границами измеряемой области. Баннер оставить отдельным нижним элементом; при обычной высоте сохранить фиксированное колесо и прежнюю прокрутку поля. Изменение высоты не должно перемонтировать колесо.
4. Проверить уменьшение/восстановление высоты, неизменность читаемых размеров, вложенную прокрутку и размещение баннера; выполнить целевые Jest, ESLint и TypeScript. Нативную проверку объявления выполняет основной исполнитель.

## Проверка игровой части

- Baseline: 34 существующих теста двух файлов прошли; новая регрессия перед исправлением упала на отсутствии ограниченной игровой области.
- После исправления: 35 тестов `layout.test.ts` и `intro-completion-navigation.test.tsx` прошли. После уточнения проверки минимального размера колеса новая регрессия повторно прошла отдельно.
- Регрессия меняет измеренную высоту 480 → 200 → 480 dp: при короткой области включается общая прокрутка, высота контента превышает viewport, буквы сохраняют минимальный размер для их количества, объявление остаётся снаружи. Колесо не перемонтируется, идентификатор попытки сохраняется.
- Целевой ESLint — без ошибок. `npx tsc --noEmit --types jest,node` — без ошибок. Общую проверку `npm run typecheck` с учётом исторических Node QA-артефактов завершает основной исполнитель; настройки TypeScript эта игровая часть не меняет.
- Расчёт `calculateGameLayout` и его API сохранены. Новый AVD не создавался; эмулятор и пользовательские данные эта часть работы не затрагивала.

## Уточнение по результатам native QA

Первая итерация общей прокрутки использовала полную `occupiedHeight` кроссворда и задач. На 320×568 это оставляло большую часть колеса ниже viewport. Внешняя высота ограничена `minimumPlayAreaHeight`, а полный кроссворд остаётся в существующей внутренней прокрутке. Регрессия теперь проверяет, что при viewport 367 dp дополнительная прокрутка не превышает 24 dp; на viewport 200 dp сохраняются читаемые буквы и небольшой резерв поля.

Финальный native QA подтвердил полный круг при входе на 320×568 и ввод слов с общей прокруткой на 320×480 со шрифтом 1.3. Общий Jest: 1378 PASS; TS и ESLint PASS. Полные доказательства и известное предупреждение SDK описаны в `sticky-banner-2026-10-30.md`.
