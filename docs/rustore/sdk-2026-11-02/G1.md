## Scope and decision

The Push plugin previously added the old unrestricted VK Maven repository. Review added the current RuStore Nexus separately, and mediation relied on Push to create its myTarget repository. A fresh prebuild could therefore keep using the old location for RuStore or lose myTarget when only the Push URL was changed.

Push, Review and mediation now share the narrow repository migration in `plugins/rustoreRepositories.js`. The project `allprojects.repositories` block contains one configured RuStore vendor repository at `https://nexus-external.rustore.ru/repository/maven-rustore-exposed`, scoped to `ru.rustore` groups. Standard Google/Maven Central resolution remains unchanged; this change does not introduce Gradle `exclusiveContent`.

In the generated project block, the old generic `https://artifactory-external.vkpartner.ru/artifactory/maven` is retained only with a `com.my.target` content filter. Mediation explicitly owns adding this repository, including on a fresh prebuild. The old RuStore-specific `/maven-rustore-exposed` URL is removed. Existing legacy generic declarations are narrowed rather than silently removing the required advertising repository.

Existing Push 6.9.1 also requires `ru.ok.tracer:tracer-lite-crash-report:1.0.1` and `tracer-manifest:1.0.1`, as declared by its published `push-core` / `pushclient` POMs. The Push plugin now owns a separate repository at `https://nexus-external.vkteam.ru/repository/maven-tracer-public-exposed`, restricted with exact `includeGroup 'ru.ok.tracer'`. Shared normalization preserves and deduplicates it through other plugin orders, and migrates explicitly scoped Tracer entries from legacy vendor declarations. Fresh Review-only or mediation-only configuration does not add it. This restores routing of already existing dependencies; no direct Tracer integration, SDK upgrade or runtime configuration is added.

All three transformations produce the same repository ownership after any plugin order, and repeated composition is stable. The helper handles the generated Groovy block, inline/multiline content filters, supported `url`, `url(...)` and `uri(...)` declarations, trailing slashes and CRLF. It preserves unrelated repositories and buildscript configuration. Unsupported target-repository clauses/groups and nested target declarations fail with a bounded error, so credentials or custom rules are not silently deleted.

Group migration accepts exact generated expressions: literal `ru.rustore.sdk` / `com.my.target` / `ru.ok.tracer`, or regex `ru[.]rustore([.].*)?` / `com[.]my[.]target` / `ru[.]ok[.]tracer`. Unrecognised expressions are rejected; a vendor-looking prefix does not prove that a regex excludes other groups. The enclosing `allprojects` block must also have a matching closing brace before any transformation.

SDK versions, app/version configuration, signing, Push project metadata, permissions and gameplay policies are unchanged. The implementation preserves the pre-existing mediation plugin and all of its unrelated dependency/compiler/memory/manifest behavior.
