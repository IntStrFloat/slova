## Exact SDK boundary

| SDK fact | App contract |
| --- | --- |
| `getAppUpdateInfo(): Task<AppUpdateInfo>` | Availability is `available`, `none`, `unknown`, `unavailable` or a typed error; transport failure is never `none`. |
| `startUpdateFlow(info, options): Task<Integer>` | `-1` is `download_accepted`; `0` is `cancelled`. Neither proves downloaded/installed. Consume the native info token before attempting launch; every retry requires fresh info. |
| `completeUpdate(options): Task<Unit>` | Both OK **and cancellation** map to SDK success. Return `flow_ended_unconfirmed`, requery after return, preserve cooldown. Never return `installed` or infer consent from Unit. |
| `DOWNLOADED=1` | Ready for a later explicit install action; not permission to interrupt play. `INSTALLING=4` is an observation, not completion. |
| `DOWNLOAD_INTERRUPTED=6`, error `4016` | Preserve the explicit observed interruption. A later `UNKNOWN=0` alone does not prove cancellation. |
| No public cancel/resume/close/cache-TTL API | Do not expose invented operations. App discard invalidates prepared metadata only; `Task.cancel`, pause, timeout and JS teardown never cancel a remote download or dismiss a form. |
| Factory creation emits SDK analytics/metrics | Disabled/QA/default capability/version inspection must never create the manager. No claimed telemetry-disable map key or internal-cache purge. |

Use `AppUpdateOptions.Builder().appUpdateType(AppUpdateType.FLEXIBLE).build()` for **both** real flow calls. No URL argument, internal/mangled info constructor, `isUsed` call, APK downloader, Expo OTA or `IMMEDIATE`/`SILENT` branch is exposed.

## Native ownership decision

Extend the **current** `RuStoreReviewModule` companion guardian, rather than add another arbiter. Keep its `activeLaunch`, observer set, `lock` and `onFormOwnerChanged`. Add one process-retained `updateFormOwner: Any?`, native-only exact-identity acquisition/release methods, and lifecycle/guardian capability version3. The public `hasActiveForm()` becomes the union of Review and Updates owners; Review prepare/launch checks the same union under the existing lock. The native token never crosses into JS.

Dependency direction is **Updates Android → Review Android**, using the autolinked local Review project (verify its resolved Gradle project name before wiring). Review never imports Updates. The Updates TS bridge does not import Review feature code. Existing JS consumers of Review's `hasActiveForm`/`subscribeFormOwnership` automatically observe either form. Current Review wrappers use exact `===2` checks: change them deliberately to accept **known2 or3** for existing Review preparation/owner subscriptions while Updates requires **3**. Unknown versions fail closed. Write tests for2/3/unknown before the capability patch; a simple native increment must not disable Review/ads readiness. No reflection, new Gradle SDK, standalone native arbitration module or cross-feature JS cycle is needed.

Updates stores its immutable native request object as that owner immediately before SDK UI launch on the main queue. Terminal callbacks release **only that exact request**, even if its React context is dead. `OnDestroy` invalidates preparation/promises but retains an open form owner. A stale/duplicate terminal callback cannot release a later form. Observer events are invalidations: subscribers read current ownership, not a queued old payload. All observers receive owner release through the existing guardian, including a newly created JS runtime.

The existing JS `tryAcquireFullscreen('update')` reservation precedes asynchronous rewarded-native checks, blocking current-runtime contenders. A positive or failed `hasActiveNativeRewardedShow()` check suppresses Updates. Recheck safety and native UI ownership immediately before launch. An actual native form retains its native owner across host pause, lost focus, module teardown and arbitrary elapsed time. No UI timeout releases ownership. A native terminal callback clears the retained owner; live JS then releases only its corresponding JS lease. Availability timeouts have no UI ownership and may invalidate their own stale request safely.

## Flags, policy and persistence

| Control | Proposed local value / scope | Behavior |
| --- | --- | --- |
| `EXPO_PUBLIC_RUSTORE_UPDATES_ENABLED` | Missing/`0` → false; exact `1` enables the app feature in a future opted-in build | Suppress new checks/offers; never erase progress/rights/cooldown or terminate open UI. |
| Native `allowRealSdk` | False unless the build explicitly enables Updates and is **not SDK QA** | Check before factory creation in every operation; capability/version getters stay pure. JS alone cannot bypass QA isolation. |
| QA real manager | Always disabled | QA route may inspect capability/version; enabled availability/download/install cases use an injected fake gateway. |
| Availability TTL | 15 minutes, app policy | Single-flight; expires at `age >= TTL`, rejects backward/future clock anomalies; pending download/install recovery bypasses ordinary TTL. |
| Native unused-info TTL | 2 minutes of monotonic time, app policy | Exact expiry, used token, context/generation/package/native version/capability change invalidates prepared info. The SDK supplies no fixed TTL. |
| In-app offer/install cancellation cooldown | Separate24-hour deadlines, app policy | Durable reservation before each form prevents restart/repeated-callback prompting. A download offer's cooldown does not block a downloaded install action. During cooldown the explicit manual listing action remains available; no automatic retry/background timer. |
| Remote control | No new Remote Config parameter in this slice | Current four-parameter allowlist/empty active experiments stay intact. A future frequency/kill-switch parameter requires a separate validated schema/protocol decision. |

The transport keeps one bounded app-owned record (`updates.state.v1`, maximum2 KiB): version1, actual `previousVersion` and optional `targetVersion` decimal strings, `attemptNo`, separate `offerUntil`/`installUntil` deadlines and a boolean `pending` recovery hint. Runtime storage write/readback confirms reservations. `pending=true` is durably reserved before the SDK call, not first written at its terminal. Fresh pending/downloading/downloaded/installing observations keep foreground recovery outside ordinary TTL; fresh none/confirmed cancellation or terminal download facts can settle it without inferring cancellation from UNKNOWN. Persist no SDK info/token, Activity, URL, release notes or exception. Corrupt/unsupported transport bytes and their cooldowns remain unchanged; they suppress the SDK offer while preserving the independent fixed manual path. Native-version change invalidates only compatible update metadata. Never clear gameplay, paid rights, refusal or Review history. Prepared info remains native memory only. Process recreation restores pending intent, then fresh-queries SDK state; it cannot replay an info object or auto-complete from a persisted `downloaded` flag.

Root explicitly approved a second, separately bounded functional marker `updates.result-attempt.v1` (maximum512 bytes): version1, one exact saved `attemptId` and a32-hex profile-scope hash from the existing pure `analyticsKeyToken` helper. No analytics ledger/identity or global ad timer is involved. The native reservation and manual final-dispatch guard both require a marker write **and exact readback before UI**. Game Continue reads this marker independently of transport validity, feature flag, component lifetime and actual native-version adoption, and skips unsolicited Review/interstitial only for the same profile/result. A new attempt/profile does not match. This separate lifecycle preserves raw corrupt/future transport data while keeping a writable manual path usable. If marker storage itself cannot be written/read back, the optional UI is refused and its lease releases; free play and the OS store path remain available. RAM-only suppression was rejected because process death loses it; GameSnapshot expansion was rejected because no gameplay/save schema change is needed. The marker replaces its prior pair; it is not a history/queue or a new reward/rights ledger.

Use native `Long` comparisons and exact decimal-string bridge values: target must be positive, same package, and strictly greater than actual installed version. Reject malformed, fractional, equal/older and precision-lost versions. `updatedAt` from store metadata is not the local cache timestamp. One application-context manager is created lazily after the gates; it is reused across Activity/JS recreation because every manager constructor registers SDK receivers. Register one actual native install listener; remove/rebind the module observer exactly during teardown/recreation without constructing another manager. There is no SDK close/purge guarantee.

Independent code/scenario probes found eight concrete JS/UI boundary gaps after the first source freeze. Keep their original probe files/results unchanged. Add regressions against actual coordinator/runtime and actual GameScreen/LevelComplete before fixing each gap:

1. Persist `pending=true` in the confirmed reservation **before** SDK UI starts. Recovered/observed pending, downloading, downloaded or installing state must bypass ordinary availability TTL until fresh terminal facts settle it; a lost callback cannot make recovery dormant.
2. Capture the displayed target and intended offer/install action at the explicit tap. A fresh query may update the displayed snapshot, but a changed target/action refuses this operation and needs another tap.
3. Reserve the manual listing's existing `update` lease synchronously before the asynchronous native-reward guard. Run that guard as a preflight inside the existing external-browser owner, preserving the same exact lease through launch acceptance and observed departure/return. Default checkout behavior stays unchanged.
4. A later offer-accepted callback must preserve all newer observed download states, including failed/interrupted. Retryable terminal download states expose the supported retry action after cooldown; a listener cannot auto-install.
5. `flow_ended_unconfirmed` explicitly triggers a fresh, single-flight status query after the SDK UI terminal, even when focus preceded it. It never implies installation and keeps install cooldown.

7. The game Menu callback returns explicit false on refusal and true only after accepted navigation. A separate root-owned widget fix makes LevelComplete unlock on false, while retaining legacy void-success behavior and the existing action slot.
