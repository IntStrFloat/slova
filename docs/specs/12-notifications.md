# 12 — Push-уведомления (RuStore)

Статус: реализовано (клиент RuStore Push 6.9.1 и локальные ежедневные напоминания), кампания 1000 уровней подготовлена · Обновлено: 2026-10-03

SDK: `react-native-rustore-push` 6.9.1 (GitFlic), подключение Expo config-plugin в `plugins/withRuStorePush.js` (зеркало `blockblast`). Провайдер активен только в Android-сборке с непустым `EXPO_PUBLIC_RUSTORE_PUSH_PROJECT_ID`; в web/Jest и без project id используется безопасный Noop.

## Поток

- **Soft-ask** открывается добровольной кнопкой «Напомнить завтра» после пяти обычных побед либо первого знакомства с ежедневным кроссвордом. Только явное согласие вызывает системный запрос `POST_NOTIFICATIONS`; автоматического диалога на холодном старте нет.
- SDK автоинициализируется через manifest `project_id`; после разрешения клиент получает device token. Сервисный токен RuStore в приложение не попадает.
- Обработка foreground/background/cold-start тапов открывает только allowlist-маршруты `/daily`, `/wheel` и `/events`; любой другой payload ведёт на `/`.

## Кампании (ретеншн)

| Триггер | Текст (пример) | Диплинк |
|---|---|---|
| Новый ежедневный пазл | «Новый пазл дня готов!» | `/daily` |
| Колесо доступно | «Крутани колесо — бесплатный спин» | `/wheel` |
| Риск потери стрика | «Не теряй серию из N дней» | `/daily` |
| Возврат D1/D3/D7 | «Тебя ждут новые слова» | `/` |
| Старт события | «Турнир начался — успей в топ» | `/events` |
| Однократно: расширение до 1000 уровней | «Теперь в игре 1000 уровней! Добавили ещё 500 уровней. Возвращайся за новыми словами!» | `/` |

- Ручные кампании запускаются из консоли RuStore. Серверный планировщик, сервисный token и хранение push-token на backend пока вне объёма.
- В консоли соблюдать cap и quiet hours. Уважать отказ игрока из settings.

### Кампания `levels-expanded-1000-v1`

Заготовка остаётся в состоянии `draft`; автоматической отправки нет. Клиент собирает аудиторию в топике `slova_levels_expanded_1000_v1`: `currentLevel` от 500 до 1000 включительно и включённые уведомления. Значение 501 после прохождения 500-го уровня подходит; прошедший 1000-й (`currentLevel = 1001`) исключается. Подписка обновляется при запуске, изменении прогресса/настроек и возврате приложения на передний план. На Android 13+ дополнительно проверяется системное разрешение без показа диалога. Выключение уведомлений удаляет токен, а выход из диапазона уровней снимает подписку с этого топика.

Топик появится только после открытия обновлённой Android-сборки с настроенным RuStore project id. У старых версий нет этой подписки; backend не хранит push-token и согласия игроков. Поэтому заготовка не обеспечивает адресную доставку всем прежним игрокам 500-го уровня, которые ещё не открыли обновление.

[Runbook одноразовой кампании](../runbooks/levels-expanded-push.md) содержит payload, dry-run и отдельный ручной запуск. Скрипт резервирует постоянный campaign id до сетевого запроса и запрещает повтор на том же операторском хосте, включая неоднозначный результат сети. Это защита от повторного запуска; гарантии exactly-once доставки RuStore нет.

## Настройки

Тумблер «Уведомления» в `/settings` доступен в Android-сборке с локальным модулем напоминаний. Включение запрашивает системное разрешение по явному действию игрока, выключение отменяет локальные напоминания и удаляет RuStore device token, когда этот провайдер доступен. После постоянного отказа Android повторный системный запрос не показывается — разрешение меняется в системных настройках приложения.

## Локальные напоминания D1/D2

Локальный Expo-модуль `modules/reminders` использует Android AlarmManager и NotificationManager. Сервис, серверная отправка и RuStore-кампании для этого сценария не нужны. Порог двух решённых ежедневных кроссвордов удалён.

- Согласие хранится независимо от тумблера в `daily.reminders.consent.v1`. Разрешение ОС или значение `notifications=true` сами по себе не дают права планировать напоминания. Новое согласие записывается только после явной кнопки и результата `granted`.
- Первое новое согласие начинает расписание **со следующего локального дня**, даже если до 18:00 ещё есть время. D1/D2 планируются на 18:00 по устройству, только для проверенного и ещё не решённого кроссворда. Продуктовая дата определяется по Москве.
- Горизонт — семь дней, максимум три уведомления за скользящие семь суток и одно за локальный/продуктовый день. Нативная проверка повторяет cap и quiet hours 21:00–10:00, когда JS не запущен. Уведомление не требует exact-alarm permission; Android может задержать доставку.
- Завершение кроссворда удаляет ожидающее и уже показанное уведомление его даты. Выключение настройки немедленно отменяет всё и сохраняет отказ отдельно, чтобы старое согласие не восстановилось миграцией.
- Однозначное старое `push.prompt.v1.outcome=allowed` мигрирует без нового холодного предложения. Старые настройки без независимого следа явного согласия требуют нового добровольного включения: отличить прежний ручной выбор от значения по умолчанию невозможно.
- Обычный перезапуск приложения, перезагрузка устройства и обновление APK сохраняют расписание подтверждённого согласия; повторная синхронизация не создаёт повторное событие для неизменённого напоминания.

## Измерение локальных напоминаний

`reminder_consent` → `reminder_scheduled` → `reminder_delivered` → `reminder_opened` → `reminder_gameplay`.

Стабильный `promptId` связывает расписание, фактическую доставку, тап и игру; `dateKey` — цель напоминания, `fireAtMs` — запланированное время, `occurredAtMs` — время нативного действия. Доставка фиксируется только после успешного `NotificationManager.notify`, а не при создании расписания. Это свидетельство публикации Android-уведомления, не доказательство просмотра пользователем.

События из закрытого приложения выгружаются при следующем открытии. У игроков, которые больше не открыли игру, локальная доставка останется неизвестной серверной аналитике. Поэтому долю открытий среди доставок нельзя считать полным delivery-to-open conversion без этой оговорки; основной эксперимент следует оценивать по всем согласившимся/назначенным игрокам и фактическому возврату к игре.

Нативный журнал читается через `readTelemetry` без удаления; JS передаёт событие в устойчивую аналитическую очередь и сохраняет журнал подтверждений с проверкой чтения. Только затем `acknowledgeTelemetry` удаляет принятые записи. Стабильные идентификаторы подавляют повтор после сбоя между чтением и подтверждением. Журналы ограничены 256 записями; нативная история отправки сохраняется 30 дней. Это восстановление с дедупликацией, а не обещание exactly-once доставки до сервера AppMetrica.

Тап принимается только для нативно доставленного напоминания. Он сохраняется при холодном запуске и `OnNewIntent`, повторный resume того же intent не создаёт ещё один тап. Реальное действие игры в течение 30 минут после тапа фиксирует `reminder_gameplay`; открытие экрана само по себе игрой не считается. При отказе от аналитики журнал очищается без отправки и атрибуции.

Корневой экран монтирует `startDailyReminderTelemetry`, синхронизация также выгружает журнал. Игровой обработчик вызывает `trackReminderGameplay` при действии игрока. Оценка роста Retention требует сравнения зрелых когорт; эти события только делают измерение возможным.

## Android-сборка

- Плагин добавляет VK Maven, manifest meta-data `ru.rustore.sdk.pushclient.project_id` и `POST_NOTIFICATIONS`.
- Пакет SDK содержит однострочную несовместимость с RN 0.85; `patch-package` применяет `patches/react-native-rustore-push+6.9.1.patch` при каждом install.
- После смены native-зависимости или project id выполнить чистый `npx expo prebuild -p android --clean` перед `bundleRelease`.

## Тесты

Jest покрывает выбор Noop-провайдера, allowlist диплинков, одноразовый soft-ask, отбор аудитории, смену токена, отказ от уведомлений и гонку подписки с удалением токена. Тесты `backend/scripts/__tests__/levels-expanded-campaign.test.cjs` проверяют dry-run, повторные/параллельные запуски и неопределённый результат запроса. Перед релизом нужен ручной smoke на Android с установленным и авторизованным RuStore: запрос разрешения, тестовая кампания и переход по тапу. Для smoke использовать отдельный тестовый push-проект, не production-топик кампании.

Локальные Jest-тесты проверяют отсутствие порога daily, D1/D2, отмену по дате, явное согласие и миграцию, отказ ОС, устойчивость журнала и связь с игрой. Нативный `ReminderTestRunner` использует только Android framework и изолированный пакет `expo.modules.reminders.test`: реальная публикация уведомления, история отправки, read/ack, приём intent с идентификатором доставленного уведомления, cap, quiet hours, восстановление после boot/update и отмена решённой даты. Команды: `:reminders:compileDebugKotlin :reminders:assembleDebugAndroidTest`; затем установить тестовый APK на тестовый эмулятор, выполнить `pm revoke expo.modules.reminders.test android.permission.POST_NOTIFICATIONS` и `am instrument -w expo.modules.reminders.test/expo.modules.reminders.ReminderTestRunner`. Разрешение отзывается до запуска: отзыв во время теста завершает его процесс. Игровой пакет и его сохранения не затрагиваются.

Проверено 2026-10-03 на Android 15 / API 35, `targetSdk=36`: 8 нативных сценариев прошли (`tests_passed=8`, `INSTRUMENTATION_CODE=-1`). Quiet hours проверяются через часовую зону только тестового процесса; часы и настройки эмулятора не меняются. Тап тестируется передачей полученного нативного идентификатора в intent; полноценный холодный переход через системную шторку и Expo Router остаётся частью smoke основной сборки. Другие версии Android и ограничения фоновой работы конкретных производителей этим эмулятором не проверены.
