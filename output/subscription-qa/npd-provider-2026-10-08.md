# Отдельный API чеков НПД: проверка 8 октября 2026 года

Схема проекта: один продавец — самозанятый без ИП; Android-игра Slova; 99 ₽ за 30 дней; первый и повторные платежи через ЮKassa. Проверка ограничена отдельным документированным API регистрации чеков, без смены эквайринга.

**Самостоятельно подключаемый боевой продукт с подтверждёнными условиями для этой схемы не найден.** Это результат проверки публичных источников, а не доказательство отсутствия индивидуального предложения у оператора. Существующие ключи SMTP или ЮKassa не дают права вызывать партнёрский API ФНС.

## Конкретный путь подключения

Приоритетный кандидат остаётся **MonetaNPD**. Его [актуальная официальная инструкция](https://docs.moneta.ru/solutions/marketplaces/registration/self-employed/) требует заявки маркетплейса на **marketplace@support.payanyway.ru**. После регистрации оператор выдаёт `security_key` и `secret_key`; публичный сценарий также предусматривает регистрацию физлица и ЭСП «МОНЕТА.РУ». Внешняя ЮKassa, договор с единственным продавцом без ИП, цена отдельного чекового API и бесплатный тест в этой инструкции не подтверждены. НКО «МОНЕТА» присутствует в [перечне операторов ФНС](https://npd.nalog.ru/aggregators/) как PayAnyWay.Self. ФНС указывает, что полномочия партнёру даёт сам налогоплательщик.

Для подключения нужны последовательные действия:

1. Отправить подготовленный [запрос оператору](../../docs/runbooks/npd-api-provider-inquiry.md) и получить письменное подтверждение именно внешних оплат ЮKassa, включая автопродления, для одного самозанятого без ИП. В этой проверке письмо не отправлялось.
2. Получить полный тариф, договор, требования идентификации, тестовые реквизиты и актуальный API-контракт. Если оператор требует заменить эквайринг или договор только с ИП/ООО, этот вариант не отвечает выбранной пользователем схеме.
3. После согласования условий оформить подключение и выдать согласованные права партнёру в «Моём налоге». Пароль личного кабинета ФНС оператору или коду игры не передавать.
4. Реализовать адаптер по выданному контракту, проверить создание/сверку/доставку/аннулирование на тестовом контуре, затем сохранить боевые ключи только на backend вне git.
5. Подтвердить настоящий чек и передачу ссылки покупателю по согласованному платежу; только после этого снимать блокировку боевых продаж.

## Недостающие условия API

Официальный [метод `registerincome`](https://docs.payanyway.ru/marketplace/samozanyatye/scenarii-ispolzovaniya-npd-api/8.-registraciya-dokhoda-v-fns-i-8.-pechat-cheka) возвращает `requestId`, а при успешной регистрации — `aisReceiptId` и `aisReceiptLink`. Есть режим синхронного запроса и автоматического повторения до результата ФНС. В опубликованном списке входных параметров отсутствуют исходная дата оплаты, внешний ID платежа/ключ идемпотентности и email покупателя. Это пробел публичной документации; нельзя придумывать эти поля или считать одинаковую подпись защитой от двойного чека. Особенно нужен документированный поиск после потери ответа до получения `requestId`.

Официальный [метод `cancelreceipt`](https://docs.payanyway.ru/marketplace/samozanyatye/zaprosy-dlya-raboty-s-fns/8.-zapros-na-stornirovanie-cheka) синхронный, принимает причину, ID чека и подпись, возвращает признак `checkIsDeleted`. На этой странице нет формулы подписи, полного порядка частичного возврата или безопасной сверки при неопределённом результате. Возврат денег по оплате ЮKassa и аннулирование записи НПД — разные операции; их связь нужно закрепить в контракте.

Доставка ссылки на чек через свой SMTP технически может быть отдельной задачей. Оператор должен сначала подтвердить регистрацию и вернуть настоящий ID/ссылку; информационное письмо об оплате не заменяет чек НПД.

## След «Ritos API Docs»

Точные публичные запросы `Ritos API Docs`, Ritos/Ритос вместе с НПД, самозанятыми, ФНС и платежами не выявили документацию российского чекового оператора. Название Ritos не найдено в просмотренном [перечне ФНС](https://npd.nalog.ru/aggregators/). Юридический оператор может называться иначе, поэтому это не окончательная проверка статуса. Без URL текущей страницы нельзя подтвердить её владельца, договор, тариф или методы. Адрес страницы и связь с уполномоченным оператором — обязательный следующий шаг, если этот след относится к подключённому аккаунту пользователя.

## Проверенный новый результат поиска

[API «Твойшаг»](https://tvoyshag.ru/api/) прямо обозначен как pre-release: API ещё прорабатывается, сроков запуска и опубликованного Swagger нет. Заявленные OAuth, идемпотентность и ресурсы `/receipts` — план. Использовать его как готовую боевую фискализацию нельзя.

**В этой проверке не создавались аккаунты, не акцептовались договоры, не отправлялись сообщения, не выдавались полномочия ФНС, не запрашивались и не читались секреты.** Спекулятивный адаптер не добавлен. Следующий предметный шаг — получить подтверждённый договор и API-реквизиты MonetaNPD либо URL и подтверждённый контракт уже открытого Ritos.
